# 毕设 · 项目说明与规模估算（**只用已冻结的内容**）

> **一句话**：这是一个 **PC 端工业上位机软件**——用 **Qt + VTK** 给 **多台（≤8）3 轴龙门式点胶机** 做 **3D 数字孪生**，含**编程可控**与**误差模拟归正**；**无真实硬件**，被控对象由**独立进程「虚拟下位机」**承担。
> **建立日期**：2026-09-21 ｜ **数据来源**：`../10-基线/S-1-立项声明.md`（v1.11 冻结）· `../10-基线/S0-需求基线.md`（v1.4 冻结）· `../20-设计/S1-架构基线草稿.md`（§十六 权威源）· `../20-设计/S1-接口清单.md`
> **口径声明**：本文**只描述已冻结/已定稿的内容**，**不含扩展设想**。

## 一、毕设题目候选（**4 个**）

| # | 题目 | 侧重 | 备注 |
|---|---|---|---|
| **A** ⭐ | **《面向多台 3 轴龙门式点胶机的数字孪生上位机设计与实现》** | 对象 + 方法 + 产物形态 | **推荐**：一句话说清"给谁做 / 做什么 / 做出什么"，"上位机"三字直接锁定**软件**属性 |

| **D** | ❌《基于一维卡尔曼滤波的点胶误差归正研究》 | 只抓一个算法点 | **不推荐**：把 1 万多行的工程缩成一个算法，**丢掉了项目最大价值（架构 + 3D + 多机）** |

### 为什么推荐 A

| 理由 | 说明 |
|---|---|
| ① **说清了"给谁做"** | 「面向多台 3 轴龙门式点胶机」—— 对象明确，且**"多台"是差异化**（行业同类产品多为单机，多机靠上层 MES） |
| ② **说清了"做什么"** | 「数字孪生上位机」—— 不含"研究""算法"这类会被追问理论深度的词，**落在工程实现上**（与项目定位 = 主力项目/工程化一致） |
| ③ **说清了"做出什么"** | 「设计与实现」—— 标准毕设句式，**含设计（架构）与实现（代码）两层**，与"可演示 + 可讲清 + 单测"的完成判据对得上 |
| ④ **不含风险词** | 无"智能""自适应""优化"等易被追问创新点的词；**"数字孪生"是唯一要准备的术语**（见 §六 风险） |

> 💡 **若学院要求题目带技术栈** ⇒ 用 **B**；**若要求在题目里体现"系统"** ⇒ A 已含"上位机"，等价。

## 二、这个项目是什么（**已确定内容，7 个维度**）

| 维度 | 已确定的内容 | 出处 |
|---|---|---|
| **① 形态** | **PC 端工业上位机软件**（不是嵌入式、不是 Web、不是手机端） | `S-1 §一 槽位` |
| **② 被控对象** | **多台（设计容量 8 台、上限可配置，演示默认 3–4 台）3 轴龙门式点胶机**；机构 = **双立柱 + 横梁，Z 轴挂于横梁 X 轴滑座**；轴定义 = **X / Y / Z 三轴直线**（Y 由龙门移动实现，工作台固定）**不含旋转轴** | `S-1 §1` · `AS-002` 已裁 |
| **③ 孪生深度** | **三层全做、均取简化版**：**T1** 3D 模型 + 实时状态映射 · **T2** + 轨迹编程/预览/校验、下发可控 · **T3** + 虚拟下位机造误差 → 上报 → 归正。<br>🔴 **对外固定表述**：「**实时双向同步的 3D 可视化 + 远程可控 + 虚拟下位机闭环**」（**不宣称行业 L3**） | `S-1 §2` · `§五 术语纪律` |
| **④ 无真实硬件** | 被控对象由**独立进程「虚拟下位机」**承担：**逐点移动 + 计时 + 误差产生**，与上位机**同机回环、经通信**（对外语义 = Modbus TCP） | `S-1 §一 附录` · `B5` · `B-012` |
| **⑤ 技术栈** | **Qt 6.10.3 + VTK 9.3**（3D 视区只用 VTK，不用 Qt Quick 3D / OpenGL）· **vcpkg + CMake** · **主程序必须走 MSVC**（VTK 是 MSVC 编的）· 持久化 = **SQLite（业务）+ JSON（配置）** · 产出 **2 个可执行 target**（上位机 + 虚拟下位机） | `S-1 §二` · `§17.2 决策 1/2/13/15` |
| **⑥ 代码规模（架构已定）** | **25 个模块**分 6 组（UI 5 / 业务 10 / 通信 2 / 存储 2 / 基础设施 5 / 独立单元 1）· **87 条依赖边**（A70/B8/D9）· **60 个抽象接口** | `§十六` · `S1-依赖边表.txt` · `S1-接口清单.md` |
| **⑦ 范围边界** | **不做 4 项**（物理量寿命/磨损预测 · 五轴/旋转轴 · 真实硬件对接 · 权限/主题/多语言/自定义布局）· **预留 10 项**（只留接口不实现）· **需求基线 127 条 + 后补 1 条 = 128 条** | `S-1 §四` · `S0` v1.4 |

## 四、🔴 开发行数预估（**推算，非实测**）

### 4.1 估算方法

**自下而上**：对 **25 个模块逐个给区间**（每个区间 = 该模块 `.h` + `.cpp` 合计，**含注释与空行**），再叠加公共头 / 构建脚本 / 测试三类。
⚠️ **与项目已有的 `P-004-b`（单切片净增 ≤400 行）同为"推算"，须在 `SLICE-00` 完成后回来校准** —— 这是项目已立的纪律。

### 4.3 叠加项

| 项 | 行数区间 | 说明 |
|---|---|---|
| 公共类型 / 接口基类（`Result` / `Vec3` / `DeviceState` / 各 `I*` 基类等） | 200–400 | 全项目共用 |

### 4.4 结论

| 口径 | 数值 |
|---|---|
| **总行数（含注释与空行）** | **约 1.0 万 ~ 1.6 万行**（中位 **≈ 1.25 万**） |
| **净代码行**（去注释 / 空行，按 ~70% 折算） | **约 7,000 ~ 1.1 万行** |
| 其中 **测试代码** | 约 800 – 1,500 行（**不计入"实现"**，但计入工作量） |
| 其中 **Markdown 设计文档** | **另计，不算代码**：本工作根 `newproject3/` 现已有 **106 个 `.md`** |

**交叉校验（用项目已有口径）**：
按 `P-004-b` 的 **单切片净增 ≤400 行** ⇒ 9,050 ÷ 400 ≈ **23 个切片**，13,500 ÷ 400 ≈ **34 个切片** ⇒ **约 23 ~ 34 个切片**。量级自洽：**25 个模块 ≈ 25+ 个切片**（一个模块大致一片）。

> ⚠️ **重要口径提醒**：本估算的**依据是"模块数与接口数"**（架构已定的硬数据），**不是"凭感觉"**。但它仍是**推算**——**`SLICE-00` 落地后必须回来校准**（项目已有此纪律，见 `60-决策记录/决策记录.md` 2026-09-19 行）。

## 五、为什么这个规模对毕设是"够用且不虚"

| 判据 | 对照 |
|---|---|
| **软件工程毕设的典型体量** | 通常 **3,000 – 8,000 行**；本项目 **1.0 万 ~ 1.6 万行**，**高于典型**（因为模块化 + 单测 + 2 个 target） |
| **是否够答辩** | ✅ **可演示性强**：3D 机构跟着坐标动、多机并排对比、误差归正后两条轨迹线重合 —— 都是**可视化可见**的东西，答辩不用靠嘴说 |
| **是否有人无我有** | ✅ **"多台统一管理 + 3D 孪生"** 是差异化：行业同类（Nordson / MUSASHI / 旗众 / 众为兴）**多为单机**，多机靠上层 MES |
| **是否有真实闭环** | ✅ **虚拟下位机是独立进程**（不是打桩 mock）⇒ **能验证"掉线即停 / 急停本地优先 / 时序"**，这是**真闭环**而非纸面闭环 |
| **是否有工程化证据** | ✅ **一键构建（CMake 配置即编译）+ 核心模块单测 + README** 三条都能给 |
| **规模风险** | ⚠️ 1 万+ 行对**单人**是重的；但项目已**明确"重活只预留"**并划了**不做 4 项 / 预留 10 项** ⇒ 范围边界是**收住**的，不是无限扩 |

## 六、⚠️ 毕设答辩的 2 个必答问题（**建议现在就想好**）

| 问题 | 必须准备好的回答（**依项目已定口径**） |
|---|---|
| **「你没有真实硬件，那这算什么？」** | ① 行业事实：**运动控制在 PLC / 运动控制卡里**，上位机本就是"专用 PC 软件" ② 本项目把"控制卡"角色**建模为独立进程**，反而能**独立验证掉线、急停、时序**（这些用真机反而不易复现）③ 接口抽象层让**换真机不改业务代码**（`REQ-COM-001`） |
| **「你说数字孪生，是几级？」** | 🔴 **依 `S-1 §五 术语纪律`：对外不出现"L3"字样**。固定表述 = 「**实时双向同步的 3D 可视化 + 远程可控 + 虚拟下位机闭环**」；若被追问层次，讲**T1/T2/T3 三层全做、均取简化版**，并**主动说明为什么不宣称行业 L3**（行业 L3 = 预测与优化，本项目明确不做物理模型） |
