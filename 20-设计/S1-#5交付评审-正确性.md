## 表二：有问题的边（逐条证据）

### 问题边 #22 —— `core/execution → core/concurrency | §17.5:下发投递`
- **出处是否支持**：✗ 失真。§17.5 数据流原文第一跳写的是：
  > `core/device(逐台下发) → core/concurrency(投递) → comm/interface → E2 虚拟下位机`
  即"下发投递"这一 hop 的**使用者是 `core/device`，不是 `core/execution`**。边表把该 hop 的源错挂到 `execution`。
- **方向本身**：execution→concurrency 作为"业务→业务"依赖方向不违理，但**挂错源**，且压制了真正的 hop（见漏边 #1）。
- **归类**：C（应改为 `core/device → core/concurrency`，或证明 execution 确有独立调度依赖并另补出处）。

### 问题边 #23 —— `core/execution → comm/interface | §17.5:下发经通信`
- **出处是否支持**：✗ 失真。§17.5 中"经通信"的 hop 是 `core/concurrency(投递) → comm/interface`（已由 A44 覆盖）。execution 在 §17.5 全链中**不出现在通信路径上**（其上游路径是 execution→device→concurrency→comm）。
- **方向本身**：execution→comm/interface 即便存在，也是 execution 越级直达通信层，与 A19+A27+A44 的"execution→device→concurrency→comm"路径**冗余**，且 §17.5 不支持。
- **归类**：C（疑似把 device 的通信职责错挂到 execution；与 #22 同源问题，并与漏边 #1 重叠）。

### 问题边 #50 —— `infra/config → core/device (B pub) | §7.2.1④(配置变更通知)`
- **出处是否支持**：✗ 自相矛盾。§7.2.1④ 原文：
  > "变更通知走 ① 的机制（`infra/eventbus`）"
  即配置变更应**经 eventbus 广播**，而非 `config` 直发 `device`。
- **是否违反方向铁律**：✓ 违反。方法 §五 禁边清单明确：
  > "`infra/* → 任何业务模块` | `§7.2.1` ②"
  `core/device` 属业务模块（core/*），故 `infra/config → core/device` 正是该禁边。且 §7.2.1② 的**全部用意**就是打破"`infra/config` 认识业务类型"的反向依赖/成环：
  > "`infra/config` 只做'加载 + 校验'，不认识任何业务类型；由启动装配点把解析结果注入各模块 ⇒ 环断开"
  本边令 config 直接发布到 device，等于**把刚断开的环又接回去**。
- **为何脚本没抓到**：`check-deps.py` 的禁边检查只对 `layer == 'A'` 生效（源码 `if layer != 'A': continue`），B 层事件边被豁免——这是脚本的**盲区**，不是边本身合法。
- **正确建模**：应拆为 `infra/config → infra/eventbus (pub)` + `infra/eventbus → core/device (sub)`，与决策17"走 eventbus"一致。
- **归类**：**D（阻塞）**——直接违反已被裁定的禁边与 §7.2.1②，必须在 #5 定稿前修正。

## 收敛小结

1. **通过率**：59 条边中 **56 条通过**、**3 条有问题**（#22 C、#23 C、#50 D）。脚本机械四项（无 A 环 / 无 A 禁边 / 端点合法 / 出处无行号）全过。
2. **漏边**：**8 项**（核心 1：`device→concurrency` 及其合法环豁免；中 2：`dashboard→comm/interface`、`alarm→execution`；低 5：config 扇入不足 / 错误码持有者缺失 / dashboard→log / eventbus 跳漏 / device→error 事件 hop）。
3. **多边**：**2 条**（#22、#23），均属"出处挂错源"，实质应合并为漏边 #1 的 `device→concurrency`。
4. **正确性结论 —— 不正确 / 未达标**：
   - 交付在"**机械可验**"层面是绿的（脚本退出码 0），但这恰好掩盖了问题：脚本**不检查 B 层禁边**（#50 的盲区），且**不核对出处真实性**（#22/#23 的伪通过）。
