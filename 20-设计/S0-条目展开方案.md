## 二、🔑 修正后的分级：**两档**（取消"轻量"）

### 为什么取消"轻量"

| 原因 | 说明 |
|---|---|
| ① 自动判定不可靠 | 试了两次：一次判出 11 条（含"可追溯性"这种不简单的）、一次判出 0 条 —— **规则本身立不住** |
| ② **"一行"正是你说"不够"的原因** | 若 30 条永久保持一行，等于**保留了一块"不够"的区域** |

⇒ **结论：所有条目至少达到「标准」档。** 没有"轻量"这一档。

### 档 1 · **标准**（**下限**，全部 111 条都要达到）

| # | 字段 | 要求 |
|---|---|---|
| 1 | ID | — |
| 2 | 条目 | 一句话 |
| 3 | **描述** | 完整陈述句，"系统应……" |
| 4 | **验收判据** | **≥ 2 条**，每条可勾选 是/否 |
| 5 | 来源 | 满足 `R3` |
| 6 | **优先级** | P0 核心闭环 / P1 完整度 / P2 加分 |
| 7 | **可测性** | 单测 / 演示 / 人工 |

### 档 2 · **深度**（**+3 字段**，共 10 个）

在标准档基础上**增加**：

| # | 字段 | 要求 |
|---|---|---|
| 8 | **前置条件** | 什么状态下才适用 |
| 9 | **异常 / 边界** | 什么情况下不成立、如何失败 |
| 10 | **依赖** | 依赖哪些条目 / 假设 |

### 深度档的**可判定规则**（满足任一即是）

| # | 条件 | 判定方式（可机械核） |
|---|---|---|
| **D-a** | **含安全语义** | 名称或判据命中：急停 / 掉线 / 超时 / 限位 / 隔离 |
| **D-b** | **含状态迁移** | 条目描述状态之间的转换（判据中出现 ≥2 个状态名） |
| **D-c** | **属闭环核心** | 名称命中：归正 / 误差 / 时序 / 插值 / I/O / 存盘读回 |
| **D-d** | **属多设备并发** | 名称或判据命中：批量 / 多设备 / 汇聚 / 隔离 |
| **D-e** | **明确要求单测** | 判据命中：单测 / 断言 |
| **D-f** | **属结构类** | ID 为 `REQ-PRC-*` / `REQ-ARCH-000` / `REQ-INF-005` |

> **方案预测**：深度 **46 条** · 标准 **65 条**｜**实际执行**：深度卡片 **50 张** · 其余走标准表
> ⚠️ **执行与方案不一致（+4）** —— 各批写作时把 4 条方案判为"标准"的条目也做成了深度卡片。
> **不算错**（多展开不损害质量），但**方案里的 46 条清单已失准** ⇒ 以**实际 50 张卡片**为准。
> ⚠️ 46 条为**规则初判**（非人工逐条定），**你可随时把某条升级或降级**。
