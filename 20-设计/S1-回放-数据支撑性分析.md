> **性质**：🔴 **架构师独立复算**（不依赖、不复用 `S1-回放-数据支撑性-主Agent复算.md` 的结论；§六 给出交叉验证）。

> **裁决依据**：`../60-决策记录/决策记录.md` 2026-09-21 行「回放功能 = **B · 只预留接口**（不实现）；且**回放须设计为独立功能模块**」—— 用户原话「回放给个预留接口，而且回放应该是一个比较独立的功能」

## 一、回放最小数据需求清单（**先立标尺，再拿它去比对**）

> **一句话**：要在 3D 场景里按时间轴重演一段历史，**逐帧**至少需要下列 13 项。**这 13 项是本文自己推演的标尺，不是 S0 里抄来的**（S0 里没有回放）。

| # | 需要的数据 | 用于重演什么 | 缺了会怎样 |
|---|---|---|---|
| **R1** | **时间戳**（有精度、有时基、跨设备可对齐） | 定帧序、定倍速、多机同场景对齐 | 帧序乱、倍速无依据、多机对不齐 |
| **R2** | **设备标识** | 回放哪一台 | 多机回放串台 |
| **R3** | **三轴实际坐标**（随时间的**位姿序列**） | 机构动起来 | 机构不动或跳变 |
| **R4** | **三轴预期 / 指令坐标** | 画"预期 vs 实际"对比线（`REQ-3D-012`） | 只有一条线，误差不可见 |
| **R5** | **设备状态时间线**（8 态，含迁移时刻） | 状态灯 / 报警重现 | 状态停在最后一帧的状态 |
| **R6** | **开胶 / 关胶（I/O）时间线** | **画出胶线**（3D 回放最直观的东西） | 只剩机构空跑 |
| **R7** | **胶路几何**（点序列 + 时间） | 胶路按时间"长出来" | 看不到胶 |
| **R8** | **误差**（偏差量 / 阈值 / 是否已归正） | 误差链路重现 | 误差曲线画不出 |
| **R9** | **执行上下文**（哪次执行 / 哪个程序 / 起止） | 定位回放区间、取出当时参数 | 不知道该放哪一段 |
| **R10** | **执行进度**（当前基元 / 点序号） | 进度高亮（`REQ-3D-007`）、浮标进度（`REQ-3D-013`） | 进度条不动 |
| **R11** | **采样节奏口径**（回放按什么粒度取帧） | 帧率与倍速 | 帧率无依据 |
| **R12** | **时段检索 + 按时间轴逐帧有序取数接口** | **能把数据取出来** | 数据在库里也放不出来 |
| **R13** | **保留期**（能回看多久） | 回放窗口 | 想回看的时段可能已被滚掉 |

## 二、现有需求**承诺存什么**（逐条读原文，**非抽样**）

### 2.1 存储类（`REQ-DB-001` ~ `REQ-DB-005`）

| REQ | 承诺存什么（原文片段） |
|---|---|
| `REQ-DB-001` | 「**四类数据可持久化** ｜ 设备/程序/工艺/**记录**重启后仍在」；判据「① 四类均持久化 ② 重启后可读」（P0） |
| `REQ-DB-002` | 「各类数据写入持久化后，读回应与写入**完全一致**」；「③ 覆盖四类表：**设备 / 程序 / 工艺 / 记录**」；异常栏「**绝对容差 1e-6 mm**（可配置）」 |
| `REQ-DB-003` | 「**可追溯查询** ｜ 可按标识查到历史生产参数」；判据「① 可按 **S/N 或时段**查 ② **结果含当时参数**」（**P2**） |
| `REQ-DB-004` | 「**选型落地** ｜ ① **SQLite**（业务数据）+ **JSON**（配置）② 配置与业务数据分离」 |
| `REQ-DB-005` | 「**数据标准化**」；判据「① 关键数据对象（设备 / 程序 / 工艺参数 / 记录）各有**唯一定义**（字段名 + 类型 + 单位 + 范围）② 同一含义**不出现两种字段名**③ 状态字段取值**复用 `REQ-STA-001` 的 8 态枚举**」 |

### 2.2 日志类（`REQ-LOG-001` ~ `REQ-LOG-009`）

| REQ | 承诺存什么（原文片段） |
|---|---|
| `REQ-LOG-001` | 「**操作日志** ｜ 参数修改应留记录（谁/何时/改了什么）」；「① 每次修改一条记录 ② 含修改前后值」 |
| `REQ-LOG-002` | 「**事件日志** ｜ 报警与状态变化应留有事件记录」；「① 每次报警产生一条记录 ② **每次状态变化**（如 运行→暂停）产生一条记录 ③ 记录含**时间戳 + 设备 + 事件类型**」；异常栏「✅ 已裁：**全记**，不做粒度筛选 —— 用户原则『**可以没用，不能没有**』」 |
| `REQ-LOG-003` | 「**记录带时间戳**」；判据「① 有**可读**时间戳 ② **排序正确**」（⚠️ 只保证可读 + 可排序） |
| `REQ-LOG-004` | 「**可按条件查询**」；判据「① 可按**时间**筛选 ② 可按**类型**筛选」（**P2**） |
| `REQ-LOG-005` | 「**通信日志** ｜ 连接的建立/断开/重连/超时/收发失败都应记录」；「③ 含对端与原因」 |
| `REQ-LOG-006` | 「**执行日志** ｜ 每次执行应记录：**设备 / 程序 / 起止时间 / 耗时 / 结果（完成·中断·急停）**」；「① 一次执行一条记录」 |
| `REQ-LOG-007` 🔑 | 「**误差日志** ｜ 每次执行的**每个点**都应记录：**预期坐标 / 实际坐标 / 偏差量 / 是否超阈值 / 本次归正修正量**」；判据「① 每点一条记录，**5 个字段齐全** ② 可按**设备 / 程序 / 时间段**查询 ③ 可**导出**（CSV）」；异常栏「点数可能很多（资料：程序可达**数万点**）⇒ 记录量大，**由 `REQ-LOG-009` 管控**」 |
| `REQ-LOG-008` | 「**系统日志** ｜ 启动 / 关闭 / 异常退出 / 恢复都应记录」 |
| `REQ-LOG-009` | 「**保留策略** ｜ 日志应有容量上限与滚动归档，并支持导出」；判据「① 达上限按策略滚动（**不得静默丢弃关键字段**）② 可导出全部或区间」 |

### 2.3 监控 / 3D / 架构冗余 / 其它（回放直接相关的）

| REQ | 承诺什么（原文片段） |
|---|---|
| `REQ-MON-001` | 「**设备状态总览**」；「④ **只有名称 + 状态色，无数值列、无表格、不可操作**」 |
| `REQ-MON-002` | 「**产量计数** ｜ ① 显示产量 ② 与实际执行一致」（P2） |
| `REQ-MON-003` | 「**数据可导出** ｜ ① 可导出 ② 内容与界面一致」（P2）⚠️ **只保证"导出"，无"导入"** |
| `REQ-MON-004` | 「**统一设备数据表** ｜ 列含：设备编号 / 连接状态 / 运行状态 / 当前程序 / 进度 / 产量 / **最近误差** / 超阈值次数」（⚠️ 只有"最近"一个标量，不是序列） |
| `REQ-3D-008` | 「**胶路结果保留** ｜ ① **执行结束后**路径仍在 ② 切换设备后该台路径可再次看到 ③ 保留份数/时长**推荐标准 = 最近 1 次**（可配置）」（⚠️ **场景内**、**最近 1 次**，非持久化） |

| `REQ-ARCH-001` | 「**趋势曲线的预留** ｜ **监控统计**数据模型保留时间序列字段」；判据「① 数据模型含时间序列字段 ② 界面预留视图位」（P2，**预留无实现**） |
| `REQ-VMC-003` | 「**上报实时坐标** ｜ 执行过程中应持续上报当前坐标」；判据「① 执行中坐标随时间变化 ② 上位机可收到**并显示**」（⚠️ 只承诺"收到并显示"，**未承诺落库**） |
| `REQ-RUN-001` | 判据「② 运行中**界面显示**当前执行到的基元序号」（⚠️ 只承诺"界面显示"，**未承诺存储**） |
| `REQ-IO-001` | 判据「① 至少含：限位 ×3 轴（输入）、**针头开胶**（输出）② **界面能显示**每个 I/O 点的**当前状态（0/1）**」（⚠️ 只有"当前值"，**无历史时间线**） |
| `REQ-ERR-006` | 判据「③ **日志逐条记、不合并**：每个超阈值点都写一条完整记录，含**设备 / 时间点 / 偏差量 / 阈值 / 是否已归正**」 |

| `REQ-NFR-008` | 「**数据刷新与 UI 刷新分离** ｜ 状态/坐标按 50ms 收取，UI（3D 渲染）按 10Hz 取最新值绘制」；判据「③ 界面显示最新值，**不堆积历史帧**」（🔴 **现有口径与回放相反**） |
| `REQ-PRM-004/005` | 「**提前开胶**可设 / **延迟关胶**可设」（⇒ 开胶时机**可算**，但算 ≠ 存） |

## 三、逐项比对（✅ 已有 · ⚠️ 有但粒度/口径不足 · ❌ 缺失 · ❓ 未定义）

| # | 需要项 | 判定 | **依据（我比对了什么）** |
|---|---|---|---|
| **R1** 时间戳 | ⚠️ | ① 通用兜底：`REQ-LOG-003`「有可读时间戳 / 排序正确」——**只保证可读与可排序，未保证分辨率、单位、单调性、跨设备时钟统一**（`REQ-DB-005` 只要求"格式统一"，不要求"时基统一"）<br>② 🔴 **`REQ-LOG-007` 保证的 5 个字段里没有时间戳**（预期坐标 / 实际坐标 / 偏差量 / 是否超阈值 / 本次归正修正量）<br>③ 仅 `REQ-ERR-006` 对**超阈值点**明确要求含「**时间点**」 | 
| **R2** 设备标识 | ✅ | `REQ-LOG-002`「时间戳 + **设备** + 事件类型」· `REQ-LOG-006`「**设备** / 程序 / 起止时间…」· `REQ-LOG-007`「可按**设备** / 程序 / 时间段查询」 |
| **R3** 三轴实际坐标 | ⚠️ | 🔴 **最强的一项支撑，但粒度与口径不足**：`REQ-LOG-007`「每次执行的**每个点**…**实际坐标**」。<br>**三点不足**：<br>**(a) "点" ≠ "帧"** —— 点 = 程序基元经 `REQ-PRG-003` 插值后的**程序点**；回放要的是**时间采样帧**。二者数量与含义都不同（空行程段无程序点）。<br>**(b) 未明写"三轴"** —— S0 里"三轴"只出现在 `REQ-3D-003`「三轴位置实时映射」与 `REQ-ERR-001`「偏移对三个轴可分别设置」；`REQ-LOG-007` 只写"坐标"，未写三轴（本文按**推论**处理，不作为已承诺）。<br>**(c) 非程序运动无坐标** —— 回零（`REQ-RUN-006`）· 点动（`REQ-RUN-008`）· 排胶（`REQ-RUN-007`）**都不产生"程序点"** ⇒ 这些运动在 `REQ-LOG-007` 里**没有记录**。<br>另：`REQ-VMC-003`「上报实时坐标」只承诺"收到并显示"，**未承诺落库** |
| **R4** 三轴预期坐标 | ✅ | `REQ-LOG-007`「**预期坐标**」+ 程序本体已持久化（`REQ-DB-001` 四类表含"程序"）+ `REQ-PRG-003` 插值可重算 ⇒ **预期轨迹两条路都能得** |
| **R5** 状态时间线 | ✅ | `REQ-LOG-002`「**每次状态变化**…产生一条记录」+「✅ 已裁：**全记**，不做粒度筛选」+ `REQ-STA-001`（8 态）+ `REQ-DB-005`③「状态字段取值复用 8 态枚举」⇒ **状态是阶跃量，事件级记录恰好完整** |
| **R6** 开胶/关胶时间线 | ❌ | 🔴 `REQ-IO-001` 只承诺「**界面能显示**每个 I/O 点的**当前状态（0/1）**」；**`REQ-LOG-001`~`009` 九条日志里没有一条是 I/O 日志**，也没有"开胶/关胶事件"记录。只能靠 `REQ-PRM-004/005`（提前开胶/延迟关胶）+ 程序**反算**，但**算 ≠ 存**，且反算拿不到"实际开胶时刻" |
| **R7** 胶路几何 | ❌ | 🔴 `REQ-3D-008`「**执行结束后**路径仍在…**推荐标准 = 最近 1 次**」= **场景内内存态、最近一次**；无任何需求把胶路写进 `data/store` |
| **R8** 误差 | ✅ | `REQ-LOG-007` **5 字段齐全**（偏差量 / 是否超阈值 / 本次归正修正量）+ `REQ-ERR-006` 逐条记录含「阈值 / 是否已归正」+ `REQ-ERR-003`「指令位置 / 实际位置 / 偏差量」⇒ **误差链路是本项目回放数据最完整的一块**（P0、可单测、可导出） |
| **R9** 执行上下文 | ✅ | `REQ-LOG-006`「设备 / 程序 / 起止时间 / 耗时 / 结果」+ `REQ-DB-003`②「结果含**当时参数**」⇒ 能定位"放哪一段"，也能取到当时工艺参数 |
| **R10** 执行进度 | ❌ | 🔴 `REQ-RUN-001` 判据②「运行中**界面显示**当前执行到的基元序号」—— 只承诺 **UI 显示**，不承诺存储；`REQ-LOG-006` 只有起止时间，**无逐点/逐基元的进度时间线** |
| **R11** 采样节奏 | ❓ | `REQ-NFR-008` 定的是**实时**收取（50ms）与渲染（10Hz），且判据③明写「界面显示最新值，**不堆积历史帧**」⇒ **现有口径与回放相反**（回放恰恰要"堆积历史帧"）。回放取帧粒度（按点 / 按 50ms / 按固定帧率）**无任何需求定义** |
| **R12** 逐帧有序取数接口 | ❌ | 🔴 `REQ-DB-003`「按 S/N 或时段查」（**P2**）与 `REQ-LOG-004`「按时间筛选 / 按类型筛选」（**P2**）都是**列表检索**语义；回放要的是「给定区间 ⇒ **按序吐帧**」。**现有需求里没有"按时间轴逐帧取数"的接口承诺** |
| **R13** 保留期 | ⚠️ | `REQ-LOG-009`「达上限按策略滚动（**不得静默丢弃关键字段**）」—— 只保证不丢**字段**，**不保证不丢记录**；且"容量上限"数值未定（`REQ-INF-006` 只要求"可配置"）。🔴 **叠加 `REQ-LOG-007` 异常栏「点数可能很多…程序可达数万点」⇒ 量最大的正是回放最需要的逐点坐标，也最可能先被滚掉** |

**计数**：✅ **5**（R2·R4·R5·R8·R9）· ⚠️ **3**（R1·R3·R13）· ❌ **4**（R6·R7·R10·R12）· ❓ **1**（R11）

## 四、结论

> # **部分能**（缺 9 项）。
>
> **能**：点位级的**轨迹重演**与**预期 vs 实际对比**（`REQ-LOG-007` 已把逐点的预期/实际坐标存下来，P0、可单测、可导出）+ **状态时间线**（`REQ-LOG-002` 全记）+ **执行上下文与当时参数**（`REQ-LOG-006` + `REQ-DB-003`②）。
> **不能**：**完整的时间轴重演** —— 尤其**胶路**（开胶/关胶与胶路几何**一项都没存**）。
> **且即使数据在库里，现在也放不出来**：没有"按时间轴逐帧有序取数"的接口（`R12` = ❌）。
> **且想回看的那段可能已经没了**：保留策略会滚动，而最容易被滚掉的正是逐点坐标（`R13`）。

### 6.3 🔴 明确反对的一条（**最重要**）

> **`S1-回放影响分析-自查版.md` 角度 1 与 `主Agent复算版` 都倾向认为「回放所需的数据基础已经预留了一半」（依据 `REQ-ARCH-001` 趋势曲线）。**
> **本文明确反对这个说法。**

| 判据 | 内容 |
|---|---|
| **① 它的落点不是轨迹** | `REQ-ARCH-001` 描述是「**监控统计**数据模型保留时间序列字段」；S1 `§六.3` 落点写「`core/stats` + `app/dashboard` ｜ 数据模型留时间序列字段」⇒ 是**产量 / 稼动率一类的标量时间序列**，**不是位姿 / 轨迹时间序列** |
| **② 它本身是"预留、无实现"** | `REQ-ARCH-001` 判据只有「① 数据模型含时间序列字段 ② **界面预留视图位**」—— 连"数据真的写进去了"都没承诺，更别说"能取出来" |
| **③ 优先级是 P2** | 它是 8 条 `REQ-ARCH-*` 架构冗余之一，P2 |
| ⇒ **结论** | 🔴 **`REQ-ARCH-001` 不构成回放的数据基础。** 真正的数据基础只有 `REQ-LOG-007`（点位坐标）+ `REQ-LOG-002`（状态事件）+ `REQ-LOG-006`（执行批次）三条，且都有本文 §四 列出的缺口 |

> 这个纠正很关键：若按"数据基础已留一半"来定接口，会**误判预留成本为零**，从而漏掉"回放将来要补数据"这件事；而本文 §四 的 G-1/G-2/G-3/G-4 全都是**将来必须补数据**的缺口 —— 它们必须**在接口上留好扩展位**，否则将来要改数据模型（成本高、且 S0 已冻结 ⇒ 得走变更单）。

## 七、对"只预留接口"裁决的意义（**回答用户第二个问题的一半**）

- **好消息**：回放**最贵的一块数据（逐点预期/实际坐标）已经存下来了**（`REQ-LOG-007`，P0、可单测、可导出）⇒ **"只留接口"的成本确实低**。
- **坏消息**：**胶路（G-2/G-3）与帧级坐标（G-1）将来必须补数据**，而补数据 = 动 S0 ⇒ **必须走变更单**。
- ⇒ **接口预留的重点**：
  1. **G-5**（按时间轴逐帧有序取数接口）—— 现在就留；
  2. **为 G-1 / G-2 / G-6 / G-7 在数据模型上留扩展位**（否则将来改模型成本高）—— 体现为 `ReplayFrame` 里 `glueOn` / `primitiveIndex` 等**字段先占位、当前恒为缺省值**。

> 具体接口设计见 `./S1-回放-独立模块接口预留.md`（第二份文件）。
