## 表四 · 轮 38 · P-5 安全链四项逐项走查

> P-5 四项（§7.1 不可配置项 + §17.2 决策 11）：急停本地优先 / 掉线即停 / 批量二次确认 / 单台故障隔离。逐项沿边表走，找"单点"（一处失效整链失效）。

### ① 急停本地优先（REQ-RUN-004，SC6）
- **走查路径**：操作员 E1 → `app/main_window`/`app/dialogs` → `core/execution` → `core/statemachine`（急停迁移）→ `core/device`（停）。
- **本地优先核验**：链中**无任何 `comm/interface` / `apps/virtual-device` 边**（急停不经通信往返）✅ —— 符合"本地优先"。
- **单点 / 断点**：边表**无 `app/* -> core/statemachine` 或 `app/* -> core/execution` 的急停/停止专用边**；仅 `app/dialogs -> core/execution`(REQ-RUN-010 作业前点检) 可复用。急停的"操作员触发"入口在边表层面**无显式边**，靠复用点检边隐含。
- **归类**：**投影已知"急停双路径(轮 22)"**（同根因）；边表级证据 = 缺 `app/*->core/statemachine` 边（I/C）。

### ② 掉线即停（REQ-RUN-009，SC7）
- **走查路径**：`comm/interface`(3s 超时判定) → `core/concurrency`(中继) → `core/device`(offline) → `core/alarm`(`core/device->core/alarm` B93 掉线→报警) → `core/execution`(`core/alarm->core/execution` 69 同步停机)。
- **单点**：**`core/concurrency` 是单中继**——`comm/interface` 的断连信号必须经它转交 `core/device`；无 `comm/interface -> core/device` 直边（禁边 comm→业务）。**若 core/concurrency 线程死，断连信号丢失→"掉线即停"整链断**，边表无"concurrency 失效"处理边。
- **归类**：**新角度**（concurrency 单点，投影并发 A9~A11 已知待设计）。

### ③ 批量二次确认（REQ-DEV-005，SC2）
- **走查路径**：`app/dialogs`(二次确认 UI) → `core/device`(逐台下发，REQ-DEV-005) → `core/concurrency`(下发投递) → `comm/interface`(E2)。
- **单点**：确认在 `app/dialogs`（UI 侧）强制；下发链 `device→concurrency→comm` 无单点（per-device 线程）。**无单点风险**（前提是 UI 不被绕过——属设计内）。
- **归类**：未发现新断点（✅）。

### ④ 单台故障隔离（REQ-DEV-006，决策 9）
- **走查路径（边表层）**：`core/device`(状态唯一持有者) + `core/concurrency`(每设备线程) 为**单节点**；隔离靠运行时"每设备一线程"（决策 9）。
- **单点 / 不可表达**：隔离性是**线程模型属性**，边表模块粒度（core/device/concurrency 各 1 节点）**无法表达**"一台卡住不牵连其它台"；且 `core/device` 作为全局状态聚合者，若进程内崩溃则所有设备状态丢失（单进程必然）。**P-5 ④ 在 #5 边表不可验证，须 #6 运行时视图补线程级**。
- **归类**：**新（范围/方法，I）**——#5 边表对安全链只能走到模块级。

### 轮 38 小结
- 四项在边表"可走通"，但**安全链全部依赖运行时机制**（concurrency 可靠性、eventbus 重放、线程隔离），边表仅到模块级。
- **共享单点**：`infra/eventbus`（所有 B 通知的通道，死则报警/状态全断）+ `core/concurrency`（掉线中继）—— 二者失效均使多项安全链断，且边表未标"失效处理"。
- 明确回答：#5 边表**不足以独立证明 P-5 四项安全**（需 #6 运行时视图补线程/失效语义）；但边表层面无禁边/环错误。
