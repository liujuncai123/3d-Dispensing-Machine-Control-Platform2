### 7.2 🔴 **配置访问架构**（"设置不能直接调用"）

> **用户要求（2026-09-20）**：「我的**其他内容比如设置也要采用良好的架构**，**而不是直接进行调用**」

**三条禁止 + 一条正确做法**：

| # | 禁止 | 为什么 |
|---|---|---|
| ❌ 1 | `Config::instance().get("ui.refresh_ms")`（全局单例 + 字符串键） | 隐式全局依赖 + **无类型检查**（写错键名编译期不报） |
| ❌ 2 | 各模块**直接读配置文件** | 违反"集中管理"（`REQ-INF-006` 判据②） |
| ❌ 3 | 把配置值当**裸值到处传**（`setRefreshMs(int)`） | 改配置项就要改一串函数签名 |

| ✅ | 正确做法 |
|---|---|
| **各模块声明自己的「配置结构体」（强类型）** | 如 `Scene3dConfig { int uiRefreshMs; LodLevel lod; }` |
| **`infra/config` 只负责**：加载 → 校验 → 组装成各模块的结构体 | 不暴露"字符串键"给业务 |
| **构造注入** | 模块构造时接收自己的结构体，**不读全局** |
| **测试时注入假结构体** | 单测不依赖真配置文件 |

> ⇒ 这条同时满足：`REQ-INF-006`（集中管理）· A3 约束 2（禁单例）· `REQ-COM-001` 的精神（依赖抽象而非具体）

### 7.2.1 🔴 五条口径补全（**2026-09-20 补**，依独立核验结果）

> **为什么补**：核验查出 §7.2 有 5 个未解问题（① 与 `REQ-INF-007` 的张力 ② `infra/config` 反向依赖成环 ③ JSON 字段名无 owner ④ 文件组织 / 变更通知 / 校验落点 ⑤ `§7.1` 措辞歧义）。
> **结论：保留原方案（强类型 + 构造注入），只补口径** —— 这 5 个问题本质是"**没说清**"，不是"**设计错**"。

| # | 问题 | **补的口径** |
|---|---|---|
| **①** | 构造注入 = 启动时**固化**，但 `REQ-INF-007` 要求运行期可改设置 | **配置分两类**：<br>**不变项**（阈值 / 上限 / 周期）⇒ **构造注入**，启动后只读<br>**可变更项**（工艺参数等）⇒ 走「**可变配置持有者 + 变更通知**」，运行时更新并广播 |
| **②** | `infra/config` 要"组装各模块结构体" ⇒ **必须认识所有业务类型** ⇒ **反向依赖、成环** | 🔴 **各模块的配置结构体定义在自己模块内**；<br>`infra/config` **只做"加载 + 校验"，不认识任何业务类型**；<br>**由启动装配点（`main` / `app` 层）把解析结果注入各模块** ⇒ **环断开** |
| **③** | JSON 字段名 ↔ 结构体字段名**无 owner**，改名即断兼容 | **结构体字段名是唯一来源**；JSON 字段名以它为准（同一份定义），纳入 `REQ-DB-005` 的"**字段唯一定义**" |
| **④** | 配置文件组织 / 变更通知 / 校验落点未定 | 配置**按模块分片**存放 · **校验**落 `infra/config` · **变更通知**走 ① 的机制（`infra/eventbus`） |
| **⑤** | `§7.1`「不可配置：急停本地优先」与 `§七`「重要设置含急停」看着矛盾 | 二者是**两个维度**，不矛盾：<br>**「不可配置」= 不能靠配置把它关掉**（安全底线）<br>**「重要设置」= 改它需要二次确认**（防误操作）<br>⇒ 急停**同时**属于两者：不可关闭，但改相关参数要确认 |

### 17.1 一句话架构策略

> ## 一套上位机管 N 台设备：**每台设备一条线程独立演进、互不阻塞**；
> ## 状态汇聚成 **唯一事实源**；**界面与 3D 只读业务状态（渲染对象自持）、不缓存**；
> ## 对下经 **通信抽象层**，换协议 / 接真机 **不改业务代码**。

**拆成五根主干（每根都有已裁依据）**：

| 主干 | 一句话 | 依据 |
|---|---|---|
| **① 多设备 = 多线程** | 每台设备一条线程，一台卡住不牵连其它台 | `B-017b` · `REQ-DEV-006` |
| **② 状态 = 唯一事实源** | `core/device` 唯一持有；`core/concurrency` **只投递不持有** | `REQ-DEV-003` · §五 硬约束① |
| **③ 上层只读** | `app/*` **只读业务状态**（渲染对象自持）、不缓存，每次读同一份 | §五 硬约束③ |
| **④ 对下抽象** | `comm/interface` 是唯一外界，`comm/modbus` 只是它的一个实现 | `REQ-COM-001` |
| **⑤ 上下解耦靠事件** | `core` **绝不依赖 `app`**；底层有事往上通知走 `infra/eventbus` | **轮 13**（查出"缺事件通道归属"；**2026-09-20 已收口为决策 17**） |

### 17.3 技术选型理由（**#19 并入** —— 面试必问的那张表）

| 选型 | 选了 | 备选 | **为什么不用备选** | 来源 |
|---|---|---|---|---|
| 整体方案 | **自研上位机** | 组态软件（组态王 / iFIX / WinCC 类） | ① 承载不了"3D 孪生 + 虚拟下位机闭环"这个核心 ② 简历项目要展示的正是**自研架构能力** | AI 分析 |
| 3D 渲染 | **VTK 9.3** | ① Qt Quick 3D ② 裸 OpenGL ③ Web 3D | ① **用户已表态否掉**（`P-006`） ② 工作量大且非本项目能力目标 ③ 不是桌面上位机形态 | `P-006` |
| 几何来源 | **图元拼** | ① 自建 CAD 模型 ② 下载现成模型 | ① 三维建模不是本项目的能力目标 ② 引入外部依赖 + 格式转换成本 | `B-008` |
| 通信 | **抽象层 + 现成 Modbus 库** | ① 业务层直接调库 ② 自己实现协议 | ① 违反 `REQ-COM-001`，换协议要改业务 ② 无收益 | `B-010` |
| 被控对象 | **独立进程虚拟下位机** | ① 上位机内部模块 ② 打桩 mock | ① 无法验证"掉线即停 / 可独立运行"（`REQ-VMC-006`）② 只能单测、**不能演示闭环** | `B5` |
| 状态机 | **自研：层次 + 表驱动** | ① `QStateMachine` ② 硬编码 if-else | ① 默认**不是表驱动**，难做"合法迁移全覆盖单测"（`REQ-STA-004`）② 非法迁移拦不住（`REQ-STA-003`） | `B-017a` |

| 构建 / 依赖 | **vcpkg + CMake** | ① 手动装依赖 ② 只用系统包 | ① **无法一键构建**（工程化判据①）② 版本锁不住 | `REQ-INF-008` |

### 17.4 权衡点清单（**#20 并入** —— 被问"为什么不做 X"时的答案）

### 17.5 架构总览（一页看懂）

| 层 | 模块 | **铁律（不可违反）** |
|---|---|---|
| **UI** | `app/main_window` · `app/scene3d`（VTK）· `app/dashboard` · `app/dialogs` · **`app/replay`**（🆕 `CR-010`） | **只读业务状态（渲染对象自持）· 不缓存** |
| **业务** | `core/device`（★**状态唯一持有者**）· `core/execution` · `core/program` · `core/statemachine` · `core/error` · `core/mapping` · `core/alarm` · `core/stats` · `core/vision` · `core/concurrency`（★**只投递不持有**） | **绝不依赖 `app`**；要通知上层**走事件** |
| **通信** | `comm/interface`（**唯一外界**）→ `comm/modbus`（一个实现） | **换协议 / 接真机不改业务** |
| **存储** | `data/log`（★**唯一写者**）· `data/store` | **单写者 + 串行化** |
| **贯穿** | `infra/config` · `infra/eventbus` · `infra/lifecycle` · `infra/telemetry` · `infra/build` | **构造注入，禁单例** |
| **独立单元** | `apps/virtual-device` | **独立进程 + 经通信 + 同机回环** |

> **合计 25 个模块** = 24 个上位机模块（UI **5** + 业务 10 + 通信 2 + 存储 2 + 基础 5）+ 1 个独立部署单元。

**数据流（一次"下发-执行"的全过程）**：

```
操作员 → app/dialogs(确认) → core/device(逐台下发)   ← 落点依 §四：REQ-DEV-004/005
      → core/concurrency(投递) → comm/interface → E2 虚拟下位机
E2 → 上报坐标/状态 → comm/interface → core/concurrency(汇聚)
      → core/device(★落成唯一事实源) → infra/eventbus
      → app/scene3d(画) + app/dashboard(显示表)
同时：core/device → core/error(算偏差) → core/alarm(超阈值告警) → data/log(留痕)
```
