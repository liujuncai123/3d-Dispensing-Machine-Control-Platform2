# 一、深度展开（11 条 · 10 字段）

## `REQ-VMC-002` · 逐点耗时（时序可单测）

| 字段 | 内容 |
|---|---|
| **描述** | 虚拟下位机执行程序时，应按设定的单点耗时推进，使该耗时可被单元测试断言。 |
| **验收判据** | ① 给定单点耗时 `t`，执行 `n` 点 ⇒ 总耗时 ≈ `n×t`（容差内）<br>② **该断言可作为一条单测**（不依赖界面）<br>③ 耗时参数可被外部设置（供 `REQ-VMC-005` 倍速使用） |
| **前置条件** | 已收到并加载程序 |
| **异常 / 边界** | 倍速模式下 `t` 按倍率缩放，**单测须覆盖 1× 与倍速两种情形**；执行被急停中断时**不补算**剩余耗时 |
| **依赖** | `REQ-VMC-001`（接收程序）· `REQ-VMC-005`（倍速）· `REQ-RUN-004`（急停中断） |
| **来源** | `B-012`（虚拟下位机必备）· S-1 §6（点名"虚拟下位机时序"） |
| **优先级** | **P0** |
| **可测性** | **单测** |
| **状态** | ⏳ 待裁 |

## `REQ-VMC-004` · 限位仿真

| 字段 | 内容 |
|---|---|
| **描述** | 虚拟下位机应模拟各轴限位，坐标到达限位时触发限位信号并使运动停止。 |
| **验收判据** | ① 坐标到达行程边界 ⇒ 产生**限位信号**<br>② 限位触发后继续下达该方向运动 ⇒ **被拒绝**<br>③ 限位信号可通过 `REQ-IO-001` 在界面上看到 |
| **前置条件** | 已加载程序或处于点动模式 |
| **异常 / 边界** | **行程范围取值待定**（建议由 S1 定，或直接取 `02-资料` 的典型值如 600×500mm）；反向运动应能脱离限位（不得锁死） |
| **依赖** | `REQ-IO-001`（I/O 显示）· `REQ-RUN-008`（点动）· `REQ-CHK-001`（越界校验） |
| **来源** | `U8`（01-资料 方向 4「传感器仿真：限位」） |
| **优先级** | **P0**（安全相关） |
| **可测性** | **单测** + 演示 |
| **状态** | ⏳ 待裁 |

## `REQ-VMC-006` · 可脱离上位机独立运行

| 字段 | 内容 |
|---|---|
| **描述** | 虚拟下位机应作为**独立进程**存在，通过通信与上位机交互（而非上位机内的一个函数）。 |
| **验收判据** | ① 虚拟下位机**可单独启动**（不依赖上位机 UI）<br>② 上位机**关闭后**虚拟下位机仍在运行（或按既定规则退出）<br>③ 二者之间**只通过通信接口**交换数据（不共享内存/全局变量） |
| **前置条件** | — |
| **异常 / 边界** | ⚠️ **本条依赖待裁的 `B5`**：若 `B5` 定为"同进程"，本条**须整体重写**；独立进程带来的好处是"上位机崩了设备仍在跑"，坏处是调试与部署更复杂 |
| **依赖** | **`B5`**（虚拟下位机是否走通信 —— **待裁**）· `REQ-COM-001`（抽象层） |
| **来源** | `B-012` + 用户裁 `B5=独立进程`（**待确认**） |
| **优先级** | **P0**（决定架构与"本地优先"边界） |
| **可测性** | **单测**（接口隔离）+ 演示（独立启动） |
| **状态** | ⏳ 待裁 |

## `REQ-IO-001` · I/O 信号可仿真与显示

| 字段 | 内容 |
|---|---|
| **描述** | 虚拟下位机应提供数字量输入 / 输出信号，且上位机可看到每个 I/O 点的当前状态。 |
| **验收判据** | ① 至少含：**限位 ×3 轴**（输入）、**针头开胶**（输出）<br>② 界面能显示每个 I/O 点的**当前状态（0/1）**<br>③ 状态变化时界面**随之更新** |

| **异常 / 边界** | I/O 点集合**可扩展**（见 `REQ-ARCH-*`）；掉线时 I/O 显示应转为"未知"而非保留旧值 |
| **依赖** | `REQ-VMC-004`（限位）· `REQ-COM-003`（连接状态） |
| **来源** | `U7`（01-资料 方向 4「信号映射与 I/O 仿真是关键环节」） |
| **优先级** | **P1** |
| **可测性** | **单测**（I/O 状态机）+ 演示 |
| **状态** | ⏳ 待裁 |

## `REQ-IO-002` · I/O 点与 3D / 状态一致

| 字段 | 内容 |
|---|---|
| **描述** | I/O 信号、3D 场景表现与设备状态三者应保持同步，不得出现"信号置位但 3D 无变化"。 |
| **验收判据** | ① 限位信号置位 ⇒ 3D 中对应轴**停在边界**且状态标记变化<br>② 开胶输出置位 ⇒ 3D 中**开始生成胶点/胶线**<br>③ 三者不一致的时长 **≤ 1 个刷新周期** |

| **依赖** | `REQ-IO-001` · `REQ-3D-005`（出胶反馈）· `REQ-3D-003`（位置映射）· `AS-001` |
| **来源** | `U7` + S-1 附录 A.1 #2/#4 |
| **优先级** | **P0**（一致性） |

| **状态** | ⏳ 待裁 |

## `REQ-ERR-001` · 固定幅度误差

| 字段 | 内容 |
|---|---|
| **描述** | 虚拟下位机在定位时叠加一个**固定幅度**的偏差，模拟系统性误差。 |
| **验收判据** | ① 每次定位的实际位置 = 指令位置 + **固定偏移**<br>② 偏移量可**被设置**（数值 = `AS-003`）<br>③ 偏移对三个轴**可分别设置** |
| **前置条件** | 虚拟下位机正在执行程序 |
| **异常 / 边界** | 偏移量若设为 0 ⇒ 等价于无固定误差（不得报错）；偏移应作用于**执行位置**而非**显示值**（否则误差就不真实） |
| **依赖** | `AS-003`（幅度取值，**待定**）· `REQ-VMC-002`（时序） |
| **来源** | S-1 §7（"固定幅度…的误差产生与上报"） |
| **优先级** | **P0**（闭环核心） |
| **可测性** | **单测**（给定偏移断言实际位置） |
| **状态** | ⏳ 待裁 |

## `REQ-ERR-002` · 随机扰动误差

| 字段 | 内容 |
|---|---|
| **描述** | 在固定误差之上叠加**随机扰动**，模拟随机性误差。 |
| **验收判据** | ① 扰动在设定**分布与幅度**内随机波动<br>② 多次执行**结果不完全相同**（证明随机性生效）<br>③ 分布参数可被设置（数值 = `AS-003`） |
| **前置条件** | 同 `REQ-ERR-001` |

| **依赖** | `REQ-ERR-001` · `AS-003` |
| **来源** | S-1 §7（"随机扰动的误差产生与上报"） |
| **优先级** | **P0** |
| **可测性** | **单测**（固定种子 ⇒ 断言可复现） |

## `REQ-ERR-004` · 归正（可单测）

| 字段 | 内容 |
|---|---|
| **描述** | 依据上报的误差计算修正量，并下发给虚拟下位机执行补偿。 |
| **验收判据** | ① 给定误差输入 ⇒ 产出**修正量**，且**修正量可被单测断言**<br>② 修正量下发后，下一次执行**应用**该修正<br>③ 修正量的计算规则**可解释**（面试可讲） |
| **前置条件** | 已有至少一次执行并收到误差 |
| **异常 / 边界** | 误差超过设定阈值 ⇒ **拒绝归正并告警**（而非产生荒谬的修正量）；归正策略**本项目为简化版**（S-1 §7 已界定：不含物理模型、不含预测） |
| **依赖** | `REQ-ERR-003`（误差上报）· `REQ-PRM-*`（若修正作用于工艺参数） |
| **来源** | S-1 §2 T3 + §6（点名"归正"） |
| **优先级** | **P0**（闭环最后一环） |
| **可测性** | **单测** |
| **状态** | ⏳ 待裁 |

## `REQ-ERR-005` · 归正后可复测

| 字段 | 内容 |
|---|---|
| **描述** | 归正之后再次执行，误差应显著减小 —— 这是"闭环有效"的证据。 |
| **验收判据** | ① 归正后再次执行 ⇒ **误差绝对值 < 归正前**<br>② 该对比**可作为演示脚本的一步**（`B-018` 闭环第 ⑦ 步） |

| **依赖** | `REQ-ERR-004` · `B-018`（演示脚本） |
| **来源** | S-1 §2 T3（"…误差模拟与归正"） |
| **优先级** | **P0** |
