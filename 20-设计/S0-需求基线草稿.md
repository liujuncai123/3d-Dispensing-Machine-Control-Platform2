## 三、需求条目长什么样（**示例**）＋ 编号规则

> **一句话**：第 1 组那 11 个"能力域"**不是最终产物**，它们只是**分组骨架**；每个能力域会被展开成若干条**需求条目**。

### 3.1 展开示意（以 `D1 3D 场景` 为例）

| ID | 需求条目 | 验收判据（可勾选 是/否） | 来源 | 状态 |
|---|---|---|---|---|
| `REQ-3D-001` | 启动后加载并显示龙门机构（图元拼） | 启动后 3D 视图区出现：底座 / 双立柱 / 横梁 / X 滑座 / Z 主轴 / 针头 | S-1 附录 A.1 #1 | ⏳ 待裁 |
| `REQ-3D-002` | 机构按虚拟坐标做几何变换（**会动**） | 下发坐标变化后，对应部件位置随之改变；刷新周期 = `AS-001` 定值 | S-1 附录 A.1 #2 | ⏳ 待裁 |
| `REQ-3D-003` | 场景内可辨运行状态 | 运行/暂停/急停/报警 四种状态在场景内**视觉可区分** | S-1 附录 A.1 #3 | ⏳ 待裁 |
| … | （其余 5 项同法展开） | … | 附录 A.1 #4~#8 | ⏳ 待裁 |

⇒ **每个能力域约展开 5~10 条**；11 个能力域 ⇒ 预估 **60~100 条**（**推算**，非实测）。

### 3.2 需求条目字段（6 个，缺一不得进基线）

| 字段 | 说明 |
|---|---|
| **ID** | 唯一、不复用 |
| **条目** | 一句话，单一动作、陈述句 |
| **验收判据** | 能勾选「是 / 否」；**禁用"实时/稳定/合理"这类词** |
| **来源** | 指向 S-1 某节，或标「S0 首次提出」——**标不出的不得进基线**（S-1 §七 R3） |
| **状态** | 待裁 / 已裁 / 已冻结 / 已作废 |
| **所属能力域** | 即第 1 / 第 2 组的编号（如 `D1` / `N2`） |

### 3.3 ⚠️ 编号规则（**尚未裁决，两个选项**）

| 选项 | 形式 | 优点 | 代价 |
|---|---|---|---|
| **A** | **按能力域前缀**：`REQ-3D-001` / `REQ-PRG-001` / `REQ-DEV-001` | 一眼看出属于哪个域；便于按域检索 | 域多了前缀也多；域改名要动 ID |
| **B** | **全局流水号**：`REQ-001` ~ `REQ-0NN` | 最简单、永不冲突 | 看不出归属，必须靠"所属能力域"字段 |

- **AI 倾向**：**A**（与 `../00-流程/02-文件结构规范.md` R4「字母代号在数字之前」一致，且更易定位）
