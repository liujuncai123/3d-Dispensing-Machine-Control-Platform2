⇒ **结论**：`CR-009` 必须连带把 `00-流程/check-consistency.py` 的两处圆括号枚举（`不做` 与 `预留` 两个正则）扩到 **⑩**（或改为按 `①|②|…|⑩` 的显式枚举 / 计数断言）。否则 v1.10 一落地，闸门立刻退出码 1，而规则⑤ 规定「退出码非 0 ⇒ 不得宣布『通过』」⇒ **变更收不了尾**。

## 2.2 简历 / README 可直接用的表述句

**A · 项目一句话（README 首段 / 简历项目描述）—— 用已裁固定表述句，不出现 L3：**

> 面向多台 3 轴龙门式点胶机的 3D 数字孪生上位机（Qt + VTK）：**实时双向同步的 3D 可视化 + 远程可控 + 虚拟下位机闭环**；按"重活只预留"原则预留 **10 项**扩展点（含**历史数据回放**），均**只留接口、不做实现**。

> · **历史回放（预留）**：按"重活只预留"原则设计为**独立模块 + 只留接口**；数据层已按时间序列建模并暴露只读通路，回放器未实现 —— **登记在案的架构取舍，非遗漏**。

## 2.3 面试官追问「回放做了吗」怎么答（1~2 句，可直接背）

> 「**没做实现，只留了接口**——这是我按判据做的取舍：回放不属于端到端闭环的必需环节，删掉它链路仍然通（编程 → 校验 → 下发 → 执行 → 3D 映射 → 误差 → 归正），所以按"重活只预留"处理，只留接口。
> 留法是：数据层按时间序列建模并暴露**只读**读取通路，回放将来作为**独立模块**接入，驱动的是 3D 场景**已有的映射通道**——将来接回放不用改任何既有模块。」

**依据可现场引**（体现"有判据"）：`../00-流程/01-开发流程.md` `P-3`「需真实数据或高成本的（…… / **文件导入**）**只留接口**」；`P-1` 的判据原话「**"没有它链路还通不通？"** 通 ⇒ 可预留；断 ⇒ 必须做」。

## 2.4 最值得讲的 **5 个要点**（把它讲成架构能力，而不是"没做完"）

| # | 要点 | 讲法（一句话） | 凭什么这么说（可指出处） |
|---|---|---|---|
| **1** ⭐ | **有判据的取舍** | 「不是没做完，是**按判据判出来的预留**：删掉回放链路仍通 ⇒ 归预留；而虚拟下位机、归正这类删了就断的 ⇒ 必须做（哪怕最简）。」 | `P-1` / `P-3` 的分界（原文：「闭环链路**上**的环节 ⇒ **简化但必须真跑**；闭环**之外**的增强 ⇒ **只预留，不实现**」） |
| **2** ⭐ | **"预留"是可验证的，不是口头承诺** | 「每条预留项都必须指出**扩展点在哪个接口 / 哪层抽象**，且这个位置**在代码里真实存在**——有一条专门的需求（`REQ-ARCH-000`）担保，否则 8 条预留会退化成空话。」 | S0 `REQ-ARCH-000` 判据①②③；S1 §6.4「9 项**逐项**给出接口点；**只留接口，不写实现**」 |
| **3** ⭐ | **为什么必须独立成模块** | 「回放的数据源（存储）与实时（通信回包）不同，**时间语义**不同（可暂停 / 跳转 / 倍速），而且它**必须禁止下发**——塞进任一现有模块都会造成"一个模块两种时间语义 + 一条不该存在的下发路径"。」 | 本文件 §三 3.2；`P-5` 安全优先 |
| 4 | **数据与可视化解耦** | 「3D 场景只认'帧数据'、不认'数据从哪来' ⇒ 实时帧与回放帧走**同一条映射通道** ⇒ 将来接回放不用改 `app/scene3d`。」 | S0 `REQ-3D-003`（三轴位置实时映射）与 `REQ-NFR-008`（数据/UI 刷新分离） |
| 5 | **安全边界** | 「回放**只读**、不进执行层；历史数据绝不触碰下发路径——这是我在方案阶段就写死的边界（P-5）。」 | `P-5`「急停本地优先 / 掉线即停 / 批量二次确认 / 单台故障隔离」；`../20-设计/S1-回放影响分析-自查版.md` 角度 5 同结论 |

> 🔑 **讲法总原则**：**先说判据（为什么不做），再说接口（怎么留的），最后说边界（为什么独立）** —— 三句话把"没实现"翻转为"有设计的取舍"。

# 第三部分 · 「独立性」的产品理由（需求侧，非架构侧）

> 用户原话：「回放应该是一个比较独立的功能」。以下从**需求边界**论证（架构落点由架构侧定）。

## 3.1 与邻近能力的边界（避免以后功能串味）

| 能力 | 时间语义 | 数据源 | 输出形态 | 能否下发 | 现有条目 |
|---|---|---|---|---|---|
| **实时监控** | **当下**（持续更新） | 通信回包实时流 | 3D + 数值 | ✅ 可（受 `P-5`） | `REQ-MON-001` · `REQ-3D-003` · `REQ-3D-013` |
| **查询检索**（可追溯） | 过去（区间），**静态结果** | 存储 | **列表 / 表格** | ❌ | `REQ-DB-003`（「可按 S/N 或时段查」）· `REQ-LOG-004` |
| **趋势曲线**（预留） | 过去（**聚合**） | 存储 | **2D 图表** | ❌ | `REQ-ARCH-001`（「数据模型含时间序列字段」） |
| **导出** | 过去 | 存储 | **文件（出系统）** | ❌ | `REQ-MON-003`（「可导出为 CSV/Excel」） |
| **预期 vs 实际对比** | **同一作业内**的对比 | 程序 + 实测 | 3D 叠加两条线 | ❌ | `REQ-3D-012` · `REQ-3D-010` 第 ③ 档 |
| **🔴 回放（新，预留）** | 过去**逐帧推进**（可播放/暂停/跳转/倍速） | 存储（+ 程序） | **3D 动态 + 状态迁移 + 轨迹重现** | 🔴 **只读，绝不下发** | 待 `REQ-ARCH-009` |

> 已有判据（不要把它们当回放）：`../30-待裁决/待裁-回放功能是否需要.md` §二 原文 ——
> 「`REQ-DB-003`｜**查询 = 列表/检索**；**回放 = 按时间轴重演**（含 3D 动态、状态迁移、轨迹重现）」；
> 「最接近的是 `REQ-ARCH-001`（趋势曲线）……**缺的是"回放器"（按时间轴驱动 3D + 状态 + 轨迹）**」。

## 3.2 四条"不串味"判据（以后任何需求进来都用它判）

| # | 判据 | 为什么 |
|---|---|---|
| **1** | **一个模块内不得同时存在"当下"与"历史帧"两种时间源** | 时间语义不同 ⇒ 状态空间不同；混在一起必然出现"当前值 vs 回放值"的歧义 |
| **2** | **凡读"过去"的能力一律不得触碰执行层的下发路径**（`P-5`） | 最大风险是"把历史数据当新程序下发"（`../20-设计/S1-回放影响分析-自查版.md` 角度 5 同结论） |
| **3** | **输出形态不复用**：2D 图表（趋势）≠ 3D 重演（回放） | 防止出现"已有趋势曲线 ⇒ 已有回放"的自我说服 |
| **4** | **生命周期不同即不同模块**：回放有播放/暂停/跳转/倍速，实时监控没有 | 这是"独立"最硬的理由：**控制状态不一样** |

## 3.3 未来若真要实现：需求**最小集**（MVP 边界）

| # | 最小集（**P0**） | 验收判据（可勾选） |
|---|---|---|
| 1 | **选段载入**：按「设备 + 时间区间」载入一段记录 | ① 可选设备与时间区间<br>② 载入失败有明确提示（无数据 / 区间非法） |
| 2 | **时间轴控制**：播放 / 暂停 / 停止 / 跳转 / 倍速 | ① 五个动作均可用<br>② **倍速档位可配置**（档位值属待定 ⇒ 走假设/待裁，不写死） |
| 3 | **3D 逐帧驱动**：回放帧经**既有映射通道**驱动机构运动 | ① 3D 随回放推进而动<br>② **复用 `REQ-3D-003` 的映射通道**，不新增渲染路径 |
| 4 | **状态与轨迹同步重现**：状态色 / 出胶 / 进度 / 胶路随帧重现 | ① 回放过程中状态与轨迹与记录一致<br>② 可用一条**单测**断言（读取→产帧，不依赖界面） |
| 5 | 🔴 **只读不下发**：回放不进执行层；UI 有**"回放模式"标识** | ① 代码层无回放→下发路径<br>② 界面有可见的模式标识<br>③ 回放期间下发入口**不可用**（或显式禁用） |
| 6 | **与实时互斥**：同一时间只有一个时间源在驱动 3D | ① 进入回放 ⇒ 实时映射让位<br>② 退出回放 ⇒ 恢复实时，且**不丢数据点**（对齐 `REQ-NFR-008`） |

**最小集之外（明确不做，防范围膨胀）**：
① 跨设备 / 多机同步回放　② 回放过程中编辑或另存　③ 回放导出为视频 / GIF　④ 回放与实时**并存**对比（属"预期 vs 实际"，见 `REQ-3D-012`）。

**数据侧最小前提（已有大半）**：`REQ-LOG-007`（误差日志）已要求「每点一条记录，**5 个字段齐全**」且「可按**设备 / 程序 / 时间段**查询」；`REQ-ARCH-001` 已要求「数据模型含**时间序列字段**」⇒ 回放的**数据基础已预留一半**，缺的只是"回放器"（`../30-待裁决/待裁-回放功能是否需要.md` §二 同结论）。
