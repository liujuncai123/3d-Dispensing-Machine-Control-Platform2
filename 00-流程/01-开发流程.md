# 01 · 开发流程（七层闸门）

> **一句话**：七层闸门，每层冻结后才许动下一层；配四条贯穿机制，专门用来终止"一检查就冒新问题"。
> **地位**：本项目**最高约束**。与本目录外的任何文件冲突时，以本文件为准。
> **依据**：用户 2026-09-19 授权确立（原话「首先你要做的就是给我一个真正的可以让我完成设计到实现的流程」）
> **来源**：产品经理「需求基线与变更控制」+ 架构师「分层闸门」两份**独立提案**的汇编
> **谁能改**：AI 只能在 `30-待裁决/` 提建议；改动本文件须用户裁决

---

## 一、为什么要有这套流程（先看这一节）

> **一句话**：上一轮的问题不是"检查不仔细"，而是**没有冻结 + 没有判据**，导致"还有问题"成为永远成立的判断。

上一轮的实证循环（记录于 `../newproject2/设计/待确定.md`）：

| 轮 | 动作 | 结果 |
|---|---|---|
| 1 | 给「功能项表」（新增内容） | 发现 N1–N5 ⇒ 出补丁（又新增） |
| 2 | 检查第 1 轮补丁 | 发现 P1–P5 ⇒ 出补丁（又新增） |
| 3 | 检查第 2 轮补丁 | 发现 Q1–Q6 ⇒ 出补丁（又新增） |

⇒ 待定区 0 → **471 行**。机制是：每轮的"补丁"都是新的未裁决内容，而补丁又成了下一轮的检查对象 ⇒ **问题是被生产出来的，不是被找出来的**。

### 四条成因（缺任一条都不会发散）

| # | 成因 | 后果 |
|---|---|---|
| 1 | **无冻结基线** | 靶子在动，检查没有对照物 |
| 2 | **检查无判据** | 退化成"自由挑错"；任何非平凡设计都永远挑得出毛病 ⇒ **这是数学必然，与设计质量无关** |
| 3 | **发现不分类** | 缺口 = 缺陷 = 改进 = 未回填的坑，全部要处理 ⇒ 处理量 ≡ 发现量 |
| 4 | **补丁是新增内容且不受检** | 自我生产问题 |

### 对照组：为什么旧项目能收敛

`../new project/docs/REVIEW-LOG.md` 跑了 192 项发现、上百轮，**最终收敛**。差别只有两点：

1. 它审的是**已定稿的文档**（有对照物）
2. 每条发现都**归到固定的 6 个根因**上，判据是"新增根因数 → 0"

⇒ **收敛的前提 = 有冻结的对照物 + 有分类器。** 本流程就是把这两样制度化。

## 二、七层闸门（主流程）

> **一句话**：每层冻结一份"可判定的裁决物"，冻结后才许动下一层；下层不许反推上层。

| 层 | 产出物 | 冻结什么 | 完成判据 DoD（可判定） |
|---|---|---|---|
| **S-1 立项声明** | 选题与目标的固化条目 | **本项目要建成什么样** | 8 个槽位全部填满，且每条带**用户原话**或**裁决依据**；无 AI 自行推导的结论冒充已定项 |
| **S0 需求基线** | 需求条目表 | 范围与验收口径 | 每条需求 = 唯一 ID + 可勾选「是/否」的验收判据 + 可追溯来源；无悬空未定量 |
| **S1 架构基线** | 模块树 / 依赖方向 / 技术栈 | 分层与职责边界 | 模块边界互斥且穷尽；依赖无环；每模块一句话说清职责 |
| **S1.5 行走骨架**（一次性，**不冻结**） | 可运行的最小链路 | — | 一条链路端到端跑通：UI 动作 → 接口 → 虚拟下位机回包 → 3D 刷新 → 1 条断言 |
| **S2 接口基线** | 接口清单 | 跨模块契约 | 每条接口 = 签名 + 前置/后置条件；**调用方与提供方描述逐条一致**；有可跑 stub |
| **S3 切片设计** | 单切片设计 + 用例 | 单切片内部方案 | 用例可执行；输入→输出确定；异常路径已列 |
| **S4 实现** | 代码 + 单测 | 代码细节（不再上溯裁决） | 单测通过；该切片可从上位机启动演示 |
| **S5 集成验收** | 演示脚本 + 验收记录 | 整机可演示基线 | 端到端演示脚本跑通；无阻断缺陷 |

**顺序铁律**：上层未冻结 ⇒ 不得开始下层。下层发现上层有问题 ⇒ 走变更单（见 `03-发现分类与变更控制.md`），**不得就地改上层**。

### 关于 S-1 立项声明（2026-09-19 增设）

> **一句话**：S-1 是 S0 的**上层对照物**，没有它则收敛判据在第一层落空。

| 项 | 说明 |
|---|---|
| **为什么需要** | D 类 = 违反已冻结条目；而 S0 是原本的第一层，**之上没有任何已冻条目** ⇒ D 类无从判定 |
| **它装什么** | 只装"本项目要建成什么样"：**选题定义 / 孪生深度 / 设备台数 / 项目定位 / 能力目标 / 完成判据 / 仿真边界 / 明确不做清单**（8 个槽位） |
| **它不装什么** | 需求条目（那是 S0 的事）、架构与模块（那是 S1/S2 的事） |
| **裁决依据** | 用户 2026-09-19 采纳 P-002-a ②a + R2 完整声明 |
| **载体** | 工作稿 `../20-设计/S-1-立项声明草稿.md` → 冻结后 `../10-基线/S-1-立项声明.md` |

> ⚠️ **禁止自证**：S-1 必须是**独立文件、独立冻结**。不得把依据写进 S0 自己的开头让 S0 自判（旧项目 G5：自评的覆盖性声明不可信）。
>
> ⚠️ **母清单第 3 项（覆盖度）在 S-1 上的特殊处理**（2026-09-19 澄清）：S-1 之上无层 ⇒ 该角度的对照物改为「**用户原话**」（留档于 `../60-决策记录/`），而非"上层已冻条目"。其余各层的覆盖度仍对照其上一层的已冻清单。

### 关于 S1.5 行走骨架

> **一句话**：先极小成本跑通一条链路，用**跑出来的事实**定接口，而不是用想象定接口。

| 做法 | 对手是谁 | 结果 |
|---|---|---|
| 先定完整设计再实现 | 想象 | 持续产生新待裁决 ⇒ 发散（已实证 471 行） |
| 先跑通骨架再定设计 | 已跑通的事实 | 收敛 |

- **位置**：S1 冻结后、S2 全量冻结前，**一次性执行，不产生冻结物**
- **最小构成**（只证"能连通"，不证"做得好"）：1 条 UI 动作 → 1 条接口 → 1 个虚拟下位机回包 → 1 处 3D 场景刷新 → 1 条断言。**不含**精度 / 性能 / 多机
- **反哺方式**：骨架跑通后，把"定不下来的问题"改写成「**已暴露的确定事实** + **仍需裁决项**」。只有确定事实进 S2；仍需裁决项进 `../30-待裁决/`
- **判据**：S2 的每条接口，要么被骨架调用证明、要么被 stub 证明，**两者皆无则该接口不得冻结**

### 关于「简化但不能没有」与「预留」（2026-09-19 用户确立）

> **一句话**：单人开发的现实约束下，功能一律**简化到最小深度**；但**闭环必需的环节一个都不能砍**，重活一律**只留接口、不写实现**。
>
> **用户原话**：「就我一个人不可能完成全部开发，这是很明显的」「简单模拟也是一个完整闭环的（重要部分）」「什么视觉、什么工艺的，我们只能说简化简化，但是**不能没有**」

| # | 原则 | 含义 | 可判定判据 |
|---|---|---|---|
| **P-1** | **闭环不可缺** | 构成端到端闭环的环节**只可简化、不可删除** | 删掉它 ⇒ 链路断掉 ⇒ 不可演示 |
| **P-2** | **简化 ≠ 删除** | 视觉 / 工艺 / 运行控制等**必须存在**，只做最小集 | 有该功能的**最小可用版本**；参数与规则按行业典型值简化 |
| **P-3** | **重活只预留** | 需真实数据或高成本的（物理量仿真 / CCD 视觉算法 / PID 自适应 / 文件导入）**只留接口** | 存在 `I*` 抽象接口 + 一个轻量实现；换实现不改调用方 |
| **P-4** | **不追求完整** | 不做"以后可能用到"的完整版 | 留接口 ≠ 写实现 |
| **P-5** | **安全优先**（2026-09-19 追加） | 因 §3 定为"多台"，**架构必须优秀且安全有保证** | ① **急停本地优先**，不依赖通信往返 ② 掉线 / 超时 ⇒ **停机**而非静默 ③ 批量下发 **二次确认** ④ 单台故障不扩散到其他台 |
| **P-6** | **状态机与线程架构先设计**（2026-09-19 追加） | 用户明确要求「整个项目的状态机和线程架构**必须要好好设计**」 | ① **S1 必须产出独立的状态机设计与线程架构设计**，二者冻结后方可进 S2 ② 状态机须能表达"急停覆盖一切"（配合 P-5）③ 线程架构须明确**哪些对象归属哪个线程**（配合 Qt 线程归属规则） |

> ⚠️ **P-1 与 P-3 的分界（易混，务必分清）**：
> 闭环链路**上**的环节（虚拟下位机、归正）⇒ **简化但必须真跑**；
> 闭环**之外**的增强（物理量仿真、预测维护）⇒ **只预留，不实现**。
>
> ⇒ 判据一句话：**"没有它链路还通不通？"** 通 ⇒ 可预留；断 ⇒ 必须做（哪怕最简）。

## 三、四条贯穿机制

> **一句话**：真正止发散的部件是**机制 2（分类）**和**机制 4（判据 + 限速）**。

### 机制 1 · 两类检查必须分开

| 维度 | 闸门验收 | 探索性审查 |
|---|---|---|
| 目的 | 判"能否冻结" | 找"还能怎么更好" |
| 输入 | **已冻结**的条目 + 其判据 | 未冻结区 / 全局视角 |
| 输出 | 每条 通过 / 不通过 | 发现清单 → **全进 `../70-Backlog/`** |
| 是否阻塞 | **阻塞**（不通过不许冻结） | **不阻塞**（绝不触发返工） |

**铁律**：探索性审查**不得**直接产出缺陷结论；要把其中某项升级为缺陷，必须走变更单并由用户裁决。

### 机制 2 · 每个发现必须四选一归类

见 `03-发现分类与变更控制.md` §一。要点：**只有 D 类能卡住冻结**；C / I / Q 各有出口，不回头污染当前层。

### 机制 3 · 冻结 = 四件套同出

一次冻结动作必须**同时**产出：

| # | 必须产出 | 作用 |
|---|---|---|
| 1 | 已冻条目清单 | 唯一对照物 |
| 2 | **明确不做清单** | 划边界，防同一问题换皮再冒出来 |
| 3 | 未决假设清单 | 带未知前进的凭证 |
| 4 | 空变更单 | 冻结后唯一入口 |

### 机制 4 · 收敛判据（**C 角度清单法**）+ 速率闸门

> **一句话**：判据是「**把母清单逐项跑完、零新增 D**」，**不是**"连续 N 轮没问题"。N 这个数字已被废止。

**收敛判据**：**同层把母清单 8 个角度逐项跑完，且新增 D 类 = 0 ⇒ 该层可冻结**

#### 母清单（固定 8 项 · 按层裁剪 · 不适用的须写一句理由）

| # | 角度 | 查什么 |
|---|---|---|
| 1 | **可判定性** | 每条能否勾选"是/否"；有无模糊词（"实时/稳定/合理"） |
| 2 | **内部一致性** | 跨节 / 跨表 / 引用 / **计数与数字** 是否自相矛盾 |
| 3 | **覆盖度** | 是否覆盖上层已冻条目（**S-1 的对照物改为"用户原话"**，见上文） |
| 4 | **依赖完整性** | 被引用对象是否存在且已冻结；**引用的出处本身是否真实存在** |
| 5 | **边界完备性** | "明确不做"是否写清；**归类是否真的落实**（不是只改了口径） |
| 6 | **协议 / 容量边界** | 是否有未定义的容量、精度、异常处理 |
| 7 | **术语一致性** | 同一概念是否用同一名称 |
| 8 | **规模与风险** | 外部依赖 / 非代码可解项是否挑出 |

- **N 不再单独拍** —— N = 该层实际采用的角度数
- **只计新增、不计存量** —— 防止"修旧账充数"式假收敛
- **C / I / Q 一律不计入"未收敛"** —— 它们有各自的出口。**这一条是整个流程的解药**
- 出现**新根因** ⇒ 该层计数器归零、补角度后重跑

#### 🔴 两条强制规则（2026-09-19 各因实际踩坑而补）

| # | 规则 | 踩过的坑 |
|---|---|---|
| **①** | **验收 / 放行一律使用本母清单**，**不得临时另编一套检查项** | 2026-09-19：放行核查临时编了"敏感信息 / 版本号 / 要素齐"三查，**未使用本母清单** ⇒ 被用户当场指出 |
| **②** | **变更单批准后的重跑 = 跑全清单**，**不是"受影响角度"** | 2026-09-19：按"受影响角度"重跑，漏掉 3 个 D（含归类未落实、计数不符、清单与定义不符）—— 变更会波及没预料到的地方 |
| **③** | 🔴 **角度 3（覆盖度）必须"逐条列出对照物、一条条勾"** —— 不许凭印象说"覆盖了" | 2026-09-19：同一角度第 1~4 轮全报"通过"，第 5 轮改了做法（真逐条比对用户原话）就查出 1 个 D（视觉未覆盖）。**这个角度不真做，必然假通过** |
| **④** | 🔴 **任何"通过"的结论，必须能指出"具体比对了哪些东西"** —— 指不出来 ⇒ 该结论无效 | 同上 |

**速率闸门**：一轮只提交**一个切片**，条目数上限由用户定；上一批未裁决完 ⇒ 不发下一批
- 已实测的违反后果：一次给 14 个模块 / 一次给 5 处补丁 / 一次给 6 处发现 ⇒ 待定区 471 行

## 四、为什么这次会停（成因 → 挡点对照）

> **一句话**：四条成因各有一个部件正对着它。

| 成因 | 被谁挡住 |
|---|---|
| 检查无对照物，自由挑错 | 机制 1：验收只对"已冻条目 + 判据" |
| 缺口全当缺陷，回头改设计 | 机制 2：C / I / Q 不返工 |
| 补丁成为下一轮检查对象 | 机制 1 + 3：补丁走变更单或进 Backlog，**都不进本轮检查面** |
| 没有判据宣布"定稿" | 机制 4：连续 N 轮零 D 即冻结 |
| 产出速率 >> 裁决速率 | 机制 4 的速率闸门 |
