# 02 · 文件结构规范

> **一句话**：规定目录怎么分、文件怎么命名、编号怎么编、状态怎么标、引用怎么写；违反本文件的产出视为无效。
> **地位**：与 `01-开发流程.md` 同级。流程管"推进方式"，本文件管"载体形式"。
> **依据**：用户 2026-09-19 授权确立（原话「我们另起一套结构，之前的结构不够规范，你来确定一个规范结构」）
> **谁能改**：AI 只能在 `../30-待裁决/` 提建议；改动本文件须用户裁决

---

## 一、为什么推翻旧结构

> **一句话**：旧结构按**话题**分文件，导致同一个文件里混了三种状态；本结构改为按**生命周期状态**分。

| 对比项 | 旧结构（`../newproject2/设计/`） | 本结构 |
|---|---|---|
| 分类依据 | 话题（`选题.md` / `待确定.md`） | **生命周期状态**（基线 / 待裁决 / Backlog） |
| 症状 | `待确定.md` 单文件 500 行，混装"已裁决 / 待裁决 / 已否决" | 三种状态切成 `10-基线/` `30-待裁决/` `70-Backlog/` |
| 命名 | 无编号，中文裸文件名，**插入文件便无法稳定排序** | `NN-名`，编号步长 10 |
| 名实相符 | `选题.md` 里塞了"目标"，被迫在 §5.7.2 讨论改名 | 一个文件一个职责；职责溢出即新建 |
| 引用 | 裸节号 + 曾用行号 | 路径 + 语义锚点，禁行号 |

## 二、目录地图（唯一权威源）

> **一句话**：九个目录，按"内容当前处在哪个生命周期状态"归位，不按话题归位。

| 目录 | 装什么 | 典型文件 |
|---|---|---|
| `00-流程/` | **怎么做事**的流程与判据（元层） | `01-开发流程.md` |
| `10-基线/` | 每层冻结后的**只读成品** | `S0-需求基线.md` |
| `20-设计/` | 当前正在做的那一层的**工作稿**（未冻结） | `S0-需求草稿.md` |
| `30-待裁决/` | **阻塞队列**：等用户拍板的条目 | `待裁决队列.md` |
| `40-假设台账/` | **Q 类**：显式未知，带最晚验证时点 | `假设台账.md` |
| `50-变更单/` | 冻结后改动的**唯一通道** | `CR-001-短名.md` |
| `60-决策记录/` | 每条决策的留档（**只追加**） | `决策记录.md` |
| `70-Backlog/` | **I 类**改进建议，不进本轮 | `backlog.md` |
| `80-资料/` | **素材**，不分"区"，只挂采用状态 | `背景资料收集.md` |

### 放置判据

> **一句话**：拿到一份内容，先问"它现在处于什么**状态**"，再按上表归位。

| 情景 | 归位 |
|---|---|
| 还没拍板的架构抉择 | 内容放 `20-设计/` 工作稿，**同时**在 `30-待裁决/` 挂一条阻塞条目 |
| 拍板了 | 内容落到 `10-基线/`，决策留一行到 `60-决策记录/` |
| 想更好但不必要 | `70-Backlog/` |
| 信息不足判不了 | `40-假设台账/`（必须带最晚验证时点） |
| 要改已冻结的东西 | `50-变更单/`（**这是唯一通道**） |

## 三、命名规范

> **一句话**：目录与主文件一律 `NN-中文名`，编号负责稳定排序，分隔符只用单连字符。

| # | 规则 | 规定 | 反例 |
|---|---|---|---|
| **R1** | 目录前缀 | 两位数字 + 单连字符，步长 **10**（留出插入空间） | `1.流程/` · `流程/` |
| **R2** | 文件前缀 | 同一目录内两位数字升序 | `名.md` · `1-名.md` |
| **R3** | 分隔符 | **只用单连字符 `-`** | `名 字.md` · `名_字.md` |
| **R4** | 制品命名 | 基线 / 切片：`S0-名.md` · `SLICE-01-名.md`（字母代号在数字之前） | `01-S0-名.md` |
| **R5** | 禁空格 | 路径全程无空格 | `10-基线/S0 需求基线.md` |
| **R6** | 中文优先 | 目录与文件名用中文保证读得懂；代号只用于前缀 | `requirements.md` |

**为什么必须有编号前缀**：在两个既有文件之间插入新文件时，**既有文件编号不需要改动**，因此既有引用不会失效。旧结构无编号，只能靠改名（而改名会让所有引用失效且无声）。

## 四、状态标记（全项目统一四种，不许自创第五种）

> **一句话**：任何条目只挂这四种状态之一。

| 符号 | 状态 | 含义 | 谁来改 |
|---|---|---|---|
| ⏳ | 待裁决 | 等用户拍板 | 用户裁决后 |
| ✅ | 已冻结 | 已固化，此后只认变更单 | 冻结动作 |
| ❌ | 已否决 | 明确不做。**留档不删、不翻案** | 用户裁决后 |
| 🔁 | 需重搜 | 仅用于资料，指取证不足需要补充 | 用户裁决后 |

## 五、引用与编辑规范

> **一句话**：跨文件引用必须「路径 + 语义锚点」；编辑必须串行且改后逐处回验。

| # | 规则 | 反例 |
|---|---|---|
| **C1** | 跨文件引用**必须带文件路径**（相对本 README） | 「见 §5.7」这种裸节号 |
| **C2** | 锚点用「节标题 + 被引原文短语」，**禁止行号引用**（改一行即失效且无声） | 「见第 42 行」 |
| **C3** | 同类信息**只有一个权威源**，别处只引用不复制 | 同一张表在两处各写一遍 |
| **C4** | 同文件**禁止并行编辑**；多处机械替换要用带计数断言的脚本，改后**逐处回验**（不得凭工具回报判定成功） | 对同一文件一次发多个 Edit |
| **C5** | 凡写「只有 N 个 / 共 N 项 / 全部已 X」这类全称判断，**必须附一条可执行的自查命令** | 凭印象写"共 14 个" |
| **C6** | 自查判据一律用**结构判据**（检查标记是否存在），不用**字样判据**（检查某词是否出现）——后者会自指误报 | 写"文件中不得出现 X 字样"作为检查规则 |
| **C7** | 🔴 **新建任何文件前，必须先列出目标目录、确认没有同主题文件** —— 否则会造重复包，违反 C3 | 2026-09-19 实际发生：`裁决包-E系列-七个缺口.md` 与既有的 `裁决包-S1-S2预告项.md` **重叠 4 项**，被迫删除 |
| **C8** | 文件名**不得包含会变化的计数**（如"八项""v2"）—— 计数一变文件名就过期 | `裁决包-S1-S2预告八项.md` → 扩到 11 项后被迫改名 |

## 六、内容格式要求

> **一句话**：每条内容要能"扫一眼就懂"，且每个数字可追溯。

| # | 要求 |
|---|---|
| **D1** | 每提一条内容（**无论已冻结还是待裁决**）必须配 **≤ 一行的一句话总结**；表格与长段落末尾要有总括句 |
| **D2** | **先给结论，再给细节** |
| **D3** | 每个断言须有出处；给不出出处的，必须显式标「假设 / 推测 / 待验证」 |
| **D4** | 每个数字标注来源（**实测 / 推算 / 估**）；写入文档前**必须当场重跑产出它的命令**，不得延用上一轮的数字 |
| **D5** | 禁止模糊表述（"大概""差不多""应该"）⇒ 换成具体值、范围，或明确的未知标注 |
