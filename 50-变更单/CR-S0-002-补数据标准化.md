## 一、为什么补

**来源**：`../80-资料/03-控制误差通信与产品对比.md` 方向 6（一套上位机管多台设备的通行做法）

> 原文：「**数据标准化**：统一数据结构（产品型号 / 点胶路径 / 目标胶量），MES 与点胶机「说同一种语言」；**统一工单编号 / 胶量阈值 / 状态字段格式**」

**S0 的现状**：只有 `REQ-DB-001`「四类数据可持久化」——**只说了"存哪四类"，没说"字段格式统不统一"**。

**为什么这条重要**：它决定**模块之间传什么**（S1 的接口设计直接依赖它）。若不统一，会出现同一个"设备 ID"在 3 个模块里叫 3 个名字。

## 二、落地

新增 **`REQ-DB-005`**（P1）：

| 字段 | 内容 |
|---|---|
| **条目** | 数据标准化（统一字段格式） |
| **判据** | ① 关键数据对象（设备 / 程序 / 工艺参数 / 记录）各有**唯一定义**（字段名 + 类型 + 单位 + 范围）<br>② 同一含义**不出现两种字段名**（如 `deviceId` 与 `dev_id` 并存）<br>③ 状态字段取值**复用 `REQ-STA-001` 的 8 态枚举**<br>④ 可用单测校验（字段命名规范检查） |
