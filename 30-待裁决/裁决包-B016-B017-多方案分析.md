## B-016 · 工艺参数的作用域

> **一句话**：工艺参数（出胶时间 / 气压 / 速度 / 提前开胶 / 延迟关胶）挂在程序、段、还是点上？

| 选项 | ✅ 优点 | ❌ 缺点 |
|---|---|---|
| **① 程序级**（整个程序一套参数） | 最简单；数据结构单一 | 无法做"某几个点换工艺"；演示时看不出工艺变化；不像真实点胶软件 |
| **② 点级**（每点可覆盖，缺省回退程序级） | 符合行业做法；演示可**逐点调工艺**；能讲"覆盖与回退"的优先级规则 | 需定义覆盖/回退规则（少量逻辑） |
| **③ 段级**（每条轨迹段一套参数） | 介于两者之间 | "段"的边界要先定义清楚，**反而多一层概念** |

- **AI 建议**：**②**
- **依据**：`../80-资料/03-控制误差通信与产品对比.md` 方向 2 —— 视觉算出的偏移是发给运动控制器侧执行，属**点/位置级**补偿；（线索来源：旧项目曾拍板"点级覆盖任务级"，**按 P-007 不继承，仅作线索**）

## B-017a · 状态机形态

> **一句话**：设备的运行状态用什么结构表达（关系到 P-5 的"急停覆盖一切"能否实现）。

| 选项 | ✅ 优点 | ❌ 缺点 |
|---|---|---|
| **① 扁平状态机**（单一状态枚举 + 迁移表） | 简单直观，实现最快 | 🔴 **无法表达"急停覆盖一切"** —— 急停的处理会散落到每个状态里，易漏 |
| **② 层次状态机 HSM**（父状态含子状态，如"运行中 > 暂停 / 空跑"） | 急停放**顶层父状态**即可全局生效；符合 P-5；语义清晰 | 实现比扁平稍复杂 |
| **③ 表驱动状态机**（迁移表数据化） | 易测试（迁移表可单测全覆盖）；加状态只改数据 | 单独用**仍解决不了覆盖问题** |
| **④ ② + ③ 结合**（层次 + 表驱动） | 兼顾"覆盖表达"与"可测性"；P-5 与 §6（单测）同时满足 | 最复杂，但复杂度可控 |

- **AI 建议**：**④**
- **理由**：P-5 要求急停本地优先 ⇒ **层次是硬需求**；§6 要求单测 ⇒ **表驱动最容易全覆盖**

## B-017b · 线程架构

> **一句话**：多设备的通信、状态汇聚与 UI 怎么分线程（§5 主攻含"多设备并发管理"）。

| 选项 | ✅ 优点 | ❌ 缺点 |
|---|---|---|
| **① 单线程事件循环 + 异步 I/O** | 最省、无锁、Qt 天然契合；不会出并发 bug | 多台设备 I/O **互相阻塞**；🔴 **讲不出并发**，与 §5 主攻冲突 |
| **② 每设备一个工作线程 + UI 主线程 + 汇聚线程** | 设备间隔离（一台卡住不影响其他）；能讲线程归属与队列 | 线程数随设备数增长 |
| **③ 线程池 + 任务队列** | 线程数可控；适合设备数多的场景 | 任务边界要切好；设备状态归属不如 ② 清晰 |
| **④ 每设备一线程 + 状态汇聚走 SPSC 无锁队列** | ② 的强化：汇聚路径用无锁队列 ⇒ **能讲你最强的并发技术点**（缓存行对齐 / 内存序 / SPSC） | 需正确实现无锁队列（**你有现成代码可复用**） |

- **AI 建议**：**④**
- **理由**：§5 主攻含"多设备并发管理"，而你简历里**并发本来就是最强项**（SPSC 无锁队列有真代码）⇒ ④ 能把最强项变成项目核心，而不是边缘功能
- ⚠️ **Qt 线程归属注意**：`QObject` 不能跨线程创建子对象 ⇒ 必须在 S1/S2 **明确"每个设备对象及其子对象归属哪个线程"**（这也是 P-6 第 ③ 条的要求）
