# 一、大局：本项目的"需求文档"是什么形状

> **一句话**：**没有"一份需求文档"**。需求不是一次写完的，是**沿着一条流水线逐层冻出来的**，每层产出一份**冻结件**，上一层的冻结件就是下一层的验收基准。

## 1.1 主流水线（七层闸门）

```
S-1 立项声明 ──► S0 需求基线 ──► S1 架构基线 ──► S1.5 行走骨架 ──► S2 接口基线
                                                                        │
                                        S5 集成验收 ◄── S4 实现 ◄── S3 切片设计
                                                          ▲            │
                                                          └── ×N 个切片 ┘
```

**核心规则**：上层冻结后才许动下层；下层发现上层有问题 ⇒ 走变更单，**不许就地改**。

## 1.2 每层是什么、产出什么、谁来看

| 层 | 产出物 | 冻结什么 | 它对谁有意义 |
|---|---|---|---|
| **S-1 立项声明** | 8 个槽位（形态 / 孪生深度 / 台数 / 定位 / 能力目标 / 完成判据 / 仿真边界 / 不做清单） | 本项目**要建成什么样** | 你、面试官（"这项目是什么"） |
| **S0 需求基线** | 需求条目表（每条带 ID + 可勾选验收判据 + 来源） | 范围与**验收口径** | 你、测试 |
| **S1 架构基线** | 模块树 / 依赖方向 / 技术栈 / **状态机** / **线程架构** | 分层与职责边界 | 面试官（"架构怎么设计的"） |
| **S1.5 行走骨架** | 一条能跑通的最小链路（**不冻结**） | — | 验证接口是否成立 |
| **S2 接口基线** | 接口清单（签名 + 前置/后置条件） | 跨模块**契约** | 编码时的唯一依据 |
| **S3 切片设计** | 单切片设计 + 用例 | 切片内部方案 | — |
| **S4 实现** | 代码 + 单测 | — | 面试官（"能演示吗"） |
| **S5 集成验收** | 演示脚本 | 整机可演示基线 | 面试官（"给我看看"） |

> 每层详细定义与 DoD 见 `00-流程/01-开发流程.md` §二。

## 1.3 为什么这么分（一句话）

**一份大需求文档会随设计变化而永远对不上；分层冻结后，每层都有一份"当时算数"的东西可对照。**

# 二、文档按"状态"分家（9 个目录）

> **一句话**：不看话题，看**这份内容现在处于什么状态**——已定？待定？要改？

| 目录 | 装什么 | 冻结性质 |
|---|---|---|
| `00-流程/` | **怎么做事**的流程与判据（元层，最高约束） | 改动需你裁决 |
| `10-基线/` | 每层**冻结后**的只读成品 | 🔒 冻后只读 |
| `20-设计/` | 当前在做的那一层的**工作稿** | 可改 |
| `30-待裁决/` | **阻塞队列**：等你拍板的条目 | AI 可追加 |
| `40-假设台账/` | **已知的未知**，带最晚验证时点 | AI 可追加 |
| `50-变更单/` | 冻结后改动的**唯一通道** | AI 提，你裁 |
| `60-决策记录/` | 每条决策的留档 | **只追加** |
| `70-Backlog/` | 改进建议，**不进本轮** | AI 可追加 |
| `80-资料/` | 行业事实素材（165 条 + 采用状态总表） | 采用权在你 |

**与旧结构的根本区别**：旧结构按**话题**分（`选题.md` / `待确定.md`），导致 `待确定.md` 一个文件塞 500 行、混装「已裁决 / 待裁决 / 已否决」三种状态。本结构把三种状态**切成三个目录**。
